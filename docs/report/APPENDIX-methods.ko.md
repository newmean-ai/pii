# 부록: 데이터 v1.0을 만드는 방법 — 방법 전체

기술 보고서([REPORT.ko.md](REPORT.ko.md))에 딸린 문서다. 보고서는 v1.0 데이터 파이프라인의 각 단계를 핵심 수치와 함께 요약하고,
이 부록은 방법 전체와 파라미터, 주의 사항을 담아 생성기 코드(공개하지 않는다) 없이도 데이터를 판단할 수 있게 한다. M1–M15 절은
보고서에서 참조한다. 시범, 검수 이력, 이전 비용, 이전 10개 레이블 모델은 [APPENDIX-experiments.ko.md](APPENDIX-experiments.ko.md)
(A–L 절)에 있다. 참고문헌 번호 [n]은 보고서 참고문헌 목록의 번호다. 모든 수치는 공개하지 않는 내부 실험 기록에서 왔으며, 공개하는 내용은 이 부록과
보고서에 담았다.

## M1. 레이블 체계와 지침

**과제.** 텍스트가 주어지면, 사람을 식별하거나 식별을 돕는 문자 스팬을 레이블과 함께 표시한다. SDK는 모델의 스팬을
마스킹한다. 모델은 구조화된 유형(이메일, 카드, IBAN, IP 주소 등)도 학습하므로 패턴에 의존하지 않는다. SDK에는 선택 사항인 패턴
계층 — 이메일, URL, 한국 주민등록번호 형태의 ID, 카드·계좌 숫자 묶음, 전화번호에 대한 단순 정규식 다섯 개로, 체크섬 검증은 없다 —
이 있지만 기본으로는 꺼져 있다. 켜면 그 스팬을 모델의 스팬에 더한다(실험 부록, O.5).

**레이블, 하위 유형, 플래그.** 모델 레이블은 13개다: PERSON, EMAIL, PHONE, ADDRESS, ID_NUMBER, FINANCIAL, ORG, USERNAME, URL,
DATE_OF_BIRTH, SECRET, 그리고 수준 2 스팬을 위한 PERSON_L2와 URL_L2(IP 주소는 ID_NUMBER로 학습한다). 데이터는 모든 스팬에 더
세밀한 **하위 유형**(subtype; 예: ID_NUMBER:passport, FINANCIAL:iban, PHONE:mobile; 총 약 75개)과 표기 방식에 대한 **플래그**를
단다 — `masked`(`**** 1234`), `partial`(잘림), `obfuscated`(풀어 쓴 형태, "kim at naver dot com"), `payment`(결제 키로 쓰인
이메일이나 전화번호). 하위 유형으로 선택적 마스킹이 가능하다("주민등록번호는 가리고 학번은 남긴다"). 모델은 레이블만 예측한다.

**PII 수준.** 모든 스팬은 수준을 받으며, 수준은 하위 유형으로 정해진다(표는 보고서 3절). 수준 2(간접)는 PERSON surname(성만
단독으로, 보통 직함이나 존칭과 함께), alias(이름처럼 쓰인 별명이나 애칭), initials, 그리고 URL public(사람을 가리키지 않는
링크)이다. 나머지는 모두 수준 1이다. 수준은 운영상의 마스킹 정책 — 사용자가 보이게 남기기로 선택할 수 있는 스팬 — 이지, 식별
가능성의 일반 분류가 아니다. 식별 가능성은 문맥과 그 밖에 알려진 정보에 달려 있다. 수준은 오류 분석에서 나왔다. 우리 이전
모델이 학습 실행마다 가장 불안정했던 스팬이 바로 별명과 성+직함 언급이었다(실험 부록, I.3).

**지침.** 영어 지침 하나를 생성 프롬프트와 검수 프롬프트에 그대로 쓴다. 지침은 레이블별로 태그할 것과 태그하지 않을 것, 스팬
경계(예: 주소는 뒤따르는 도시를 포함한다; 이름은 존칭과 문법적 어미를 뺀다 — 터키어 "Ayşe'nin" → Ayşe, 한국어 "서윤이" →
서윤), 겹침 규칙(태그는 중첩하지 않는다; 토큰이 들어 있는 URL은 SECRET이다), 그리고 검수 중에 찾은 문화별 규칙(태국어,
베트남어, 인도네시아어에서 직함 뒤의 이름은 성이 아니라 이름이다; 중국어 호칭 접두사 小/老/阿(小张, 老王처럼)는 이름에서
뺀다)을 정한다. 지침은 11개 버전을 거쳤다. 지침 원문은 그것이 들어가는 생성·검수 프롬프트와 마찬가지로 공개하지 않으며, 이 절에 그 규칙을
요약했다.

## M2. 설계 축

생성 호출 한 번은 모델에게 한 언어·한 국가로 40개 항목을 요청한다. 계획기(planner)는 언어별로 국가(화자 수로 가중; 54개 언어에
79개 로케일)와 16개 영역(의료, 금융, 교육, 인사, 고객 지원, 법률, 행정, 전자상거래, 여행, 통신, 연구 설문, …)을 나누고, 항목별로
20개 형식(채팅 메시지, 이메일, 양식, CSV 행, JSON, 로그 줄, 스캔한 양식의 OCR 텍스트, 코드 조각, …) 중 하나, 길이, 화자(voice;
예: 비원어민 작성자, 노인, 십대, 전문직), PII 개수(없음 / 하나 / 둘 이상), 변형 요소(twist; 풀어 쓴 값, 코드 전환, 같은 사람을
다른 형태로 다시 언급, 여러 줄에 흩어진 PII, 지명·브랜드명 같은 어려운 음성 예(hard negatives), 남아시아 언어의 로마자 표기,
외국인 거주자 이름)를 나눈다. 각 항목은 빈도 가중치로 뽑은 **필수 초점 하위 유형**도 받으므로, 드문 유형(MRZ 개인번호, IBAN,
카드 유효기간, 복구 문구, 돌봄 제공 기관)도 충분한 수만큼 나온다. 배분은 표집이 아니라 정확한 할당량(내림 후 최대 나머지
방식)으로 하며, 모든 호출에 각자의 시드가 있다.

## M3. PII 없는 항목

**PII 없는 항목**은 설계상 전체 항목의 40%다(실제 입력 글에는 개인정보가 없는 경우가 많고, 그런 글을 드물게 본 모델은 과잉
마스킹한다). 이 항목들은 자기만의 변형 요소 목록에서 뽑으므로, 어려운 음성 예가 브랜드명과 지명에 그치지 않는다. 닮은 숫자
(주문·티켓·송장 번호, 모델 코드, 가격, 일반 날짜, 버전 번호, 3–5자리 단축 코드), 역할이나 관계로만 언급되는 사람, PII가 아닌
이름(지명, 브랜드, 그 사람이 물건을 사기만 하는 가게 — 직장·학교·병원은 아님), 양식이나 자리표시자 텍스트(빈 칸, `[Name]`, 완전히
가린 값), 이름 없는 코드 전환이 그것이다. 약 53%(v1.0 검증셋에서 52.7%)가 변형 요소를 받고, 점검한 행의 99–100%에서 글이 그
변형을 따르며(닮은 숫자에는 숫자, 자리표시자에는 괄호나 별표), 이 행들에는 스팬이 하나도 없다. (PII 없는 항목에 자기만의 변형
요소 목록이 생기기 전에는 그중 11%만 변형 요소를 가졌다; 실험 부록, C.)

## M4. 국가 형식

모든 로케일마다 형식 카드가 현지 식별번호의 모양(국가 신분 번호, 세금 번호, 여권, 체류 허가, 건강·사회보험 번호, 전화번호 체계,
우편번호, 은행 계좌·IBAN 형식, 자동차 번호판)을 담는다. 공식 자료를 조사해 만들었고, 신뢰도 메모와 정규식을 함께 기록했다. 값은
체크섬이 아니라 **형식**에 맞아야 한다 — 체크섬이 틀리면 실제 사람의 번호와 겹칠 가능성이 줄어든다. 형식 검사가 생성된 값을
명세와 대조해 검증한다. 실패는 조용히 버리지 않고 검토한다. 생성기 오류일 수도 있지만 명세의 빈틈일 수도 있기 때문이다 — 이
검토로 약 40개국의 명세를 고쳤다(실험 부록, D). v1.0에서는 검사 가능한 값의 0.5%가 검사에 실패하며(검증셋), 그런 행은 검토
표시가 붙어 학습에서 빠진다.

## M5. 이름과 외국인 거주자

언어 모델은 적은 수의 이름을 반복해 쓰고, Faker [60]는 우리 로케일 중 일부만 다룬다(실험 부록, E). 우리는 79개 로케일 모두에
대해 Wikidata(CC0) [58]로 이름 풀을 만들었다. 남녀별 이름(given name)과 성(family name)을 담고, 그 이름을 가진 Wikidata 인물
수로 빈도를 셌으며, 현지 문자 표기와 라틴 문자 표기를 함께 둔다. 빈도가 낮은 항목은 잡음이 많아서 빈도 1인 꼬리는 버리고 가중치
count^0.25로 표집한다. 이름과 성은 남녀를 맞춰 조합한다. 성에 남녀 형태가 따로 있는 13개 언어에서는 여성형을 만든다(Иванов →
Иванова, Novák → Nováková, Kowalski → Kowalska, Kazlauskas → Kazlauskienė, Jónsson → Jónsdóttir). 베트남어 이름은 성 + 중간
이름 + 이름으로 구성한다.

**외국인 거주자.** 실제 텍스트에는 다른 나라 이름 — 이주 노동자, 학생, 관광객 — 이 들어 있다. UN DESA International Migrant
Stock 2024 [59]를 이용해(한국과 일본은 국가 통계) 호출마다 외국 이름 2–3개를 뽑는다. 80%는 해당 목적국의 주요 출신국에서,
20%는 전형적인 방문객 출신국에서 뽑으며, 추가 출신국 풀 54개를 쓴다(모든 목적국은 출신 비중의 ≥ 90%가 포함된다). 항목의 8%에
붙는 변형 요소는 생성기에게 그런 이름을 로마자로(순서, 하이픈, 대소문자가 다양하게) 쓰거나 현지 문자로 음역해 쓰라고 요청한다.
v1.0 검증셋에서 다른 호출에 다시 나오는 전체 이름은 언어별 전체 이름 스팬의 중앙값 1.4%다(가장 높은 것은 몰타어 11.8%로, 실제
몰타 성이 몇 개에 몰려 있다).

## M6. 생성 모델, SECRET 재배정, 출력 형식

세 Claude 모델이 데이터를 쓴다. 각 모델의 역할은 시범 감사와 비용에 따라 정했다(실험 부록, A).

| 생성기 | v1.0에서의 역할 | 호출당 비용 (40행, Message Batches) |
|---|---|---|
| Claude Haiku 5.5, effort high | 학습·검증 데이터의 90% | $0.0104 |
| Claude Sonnet 5.5, effort high | 학습·검증 데이터의 10%, 테스트셋의 50%, 테스트의 모든 SECRET 값 | $0.098 |
| Claude Opus 5.5, effort high | 테스트셋의 50% | ≈ $0.2 |

학습과 테스트에 다른 생성기를 쓰면 벤치마크가 한 모델의 문체에 보상할 위험이 줄어든다.

**SECRET 재배정.** Opus는 비밀값(API 키, 개인 키)을 요청하는 작업을 거부하므로, SECRET 초점 항목은 Opus 작업에서 같은 언어의
Sonnet 작업으로 옮기고(같은 국가 우선, 다음은 같은 영역; 받는 작업 하나에 최대 6개, 더 적게 받은 작업이 있는 동안에는 그쪽으로),
Opus 프롬프트에는 가짜 비밀값을 넣지 않으며, 그래도 남은 거부는 Sonnet으로 다시 생성한다. 따라서 테스트셋의 SECRET 스팬은
Sonnet만 썼다(한계; 보고서 7절).

**출력 형식과 실패 처리.** 각 호출은 항목을 번호별로, 인라인 태그가 붙은 텍스트로 돌려준다.
`<LABEL:subtype+flag>value</LABEL>`(예: `<PHONE:mobile>010-…</PHONE>`). 파서는 태그를 벗겨 문자 오프셋으로 바꾸며, 태그가
중첩되거나, 짝이 안 맞거나, 닫히지 않았거나, 비어 있거나, 등록되지 않은 PII 비슷한 태그(`<EMAIL_ADDRESS>`)를 쓴 항목은
거부한다. 실패하거나, 잘리거나, 항목을 덜 돌려준 호출은 같은 프롬프트로 다시 생성한다. 거부된 호출은 Sonnet으로 다시 생성한다.
프롬프트는 스팬 경계의 자체 점검으로 끝난다(존칭과 문법적 어미는 이름 밖에, 주소에는 도시와 건물을 포함, 계좌에는 은행명을
포함, 조직에는 부서를 포함).

## M7. 배치·실시간 생성과 고정된 입력

전체 라운드는 Message Batches API(50% 할인)로 돌린다. 백 건 안팎의 시범 호출과 라운드 끝에 남은 몇 건의 실패분은 정가 실시간
API로 보낸다. 배치는 큐에서 한 시간을 기다리기도 하기 때문이다. 한 라운드는 기본 시드가 서로 다른 샤드로 나뉘므로 샤드마다
할당량 조합이 다르다. 첫 제출 때 라운드는 행을 만드는 모든 입력 — 지침, 국가 명세, 이름 풀, 생성기 코드, 생성 뒤 값 바꾸기
(M8) — 의 해시를 고정하고, 하나라도 바뀌면 이후 제출을 거부한다. 모든 프롬프트와 원본 응답을 저장하므로, 파서나 값 바꾸기가
바뀌면 새 API 호출 없이 원본 응답에서 라운드의 행을 다시 만들 수 있다(계획기가 검증셋 항목
명세 53,950개를 모두 정확히 재현한다). 일반적인 실행: 검증 호출 1,350건에 큐 대기 약 35–75분, 호출의 1–3%가 실패하거나 잘려 다시 생성됐다.

## M8. 생성 뒤 값 바꾸기

생성기는 자연스러운 값 풀이 없는 유형 — 카드 유효기간, CVV, 일회용 인증 코드, 응답자 코드, 일반 날짜 — 에서 좋아하는 값으로
쏠리고(값 바꾸기 전에는 유효기간 하나가 전체 유효기간 스팬의 3분의 1 이상이었다), 프롬프트에 새 예시 값을 주어도 무시한다(실험
부록, C). 그래서 이 값들은 파싱 뒤에 행마다 결정적으로 바꾼다.

- 카드 유효기간(월은 무작위, 연도는 생성된 값의 ±1 이내), CVV, 일회용 인증 코드, 응답자 코드 스팬의 숫자를 바꾼다. 한 행에
  같은 값이 두 번 나오면 같은 값으로 바꾼다.
- 스팬 밖의 일반 날짜는 무작위로 정한 하나의 일수(−18개월~+6개월)만큼 함께 옮겨 순서와 간격을 지킨다 — 다만 그 행에 요일
  이름(그 언어와 영어의 CLDR 이름)이 있거나, 연도만 따로 쓰였거나, 생년월일이 있으면 그 행의 날짜는 그대로 둔다(옮기면 글과
  모순된다. 예: 날짜 옆의 요일).
- 아이슬란드 kennitala는 맞는 세기 숫자를 받는다.

스팬 오프셋은 다시 계산하며 다른 스팬은 바뀌지 않는다. v1.0 검증셋에서 가장 흔한 값의 비율은 3.3%(유효기간), 2.2%(CVV),
0.3%(일회용 인증 코드), 0.4%(응답자 코드), 2.4%(글 속 날짜)로 내려간다.

## M9. 자동 점검 관문

모든 라운드는 다음을 검사한다: 항목 명세에 맞는 행(PII 개수, 필수 하위 유형 포함 ≥ 95%), 검사 가능한 스팬의 형식 유효성
(≤ 1%), 다른 언어 텍스트(≤ 0.5%; 로마자로 쓴 남아시아 채팅과 CSV 비슷한 표는 오경보로 밝혀진 뒤 예외로 둠), 카드 예시 복사,
그리고 계약(contract) 위반에 대한 검토 대기열. 검사에 실패한 행은 해결될 때까지 학습에서 뺀다.

## M10. 블라인드 이중 검수

**표본 추출.** 표본은 두 종류다. 탐지기가 표시한 행의 *풀*(pool; 우리 교사 모델과 공개 모델이 생성된 레이블과 어긋나는 행,
또는 확인할 새 레이블 유형이 있는 행)과, 풀 밖의 행에서 균일하게 뽑은 *무작위 감사*(random audit; 풀을 만들지 않으면 라운드
전체에서 뽑는다)다. 라운드 전체에 대한 추정치는 두 변경률을 모집단 크기로 가중한 합이다(풀 비율 × 풀 크기 + 감사 비율 × 풀 밖
행 수). 감사만으로는 풀 밖의 행만 추정한다. 따라서 라운드마다 감사 비율은 서로 다른 모집단을 나타낸다.

**검수.** 서로 다른 모델 계열의 두 검수자 — Claude(Opus)와 GPT-6.1 Sol(codex CLI 사용) — 가 표본으로 뽑힌 각 행을, 생성된
레이블도 서로의 결과도 보지 않고, 지침과 함께 **원문만 보고** 다시 태그한다.

**정의.** 두 검수자가 같은 스팬과 레이블을 내고 그것이 생성기의 것과 다르면 그 행은 *변경*된 것이다. 검수자끼리 다르고 한쪽이
생성기와 같으면 생성기 레이블을 유지한다. 어느 쪽도 같지 않으면 그 행은 사람의 판정을 위해 보류하고 그때까지 학습에서 뺀다.
하위 유형은 검수자들이 일치하면 검수자의 것을, 아니면 생성기의 것을 쓴다. 변경률은 오류율이 아니라 합의된 변경의 비율이다. 두
검수자가 함께 저지른 오류는 놓치고, 잘못된 변경이 포함될 수 있다(한 시범 감사에서 합의된 변경 39건 중 1건이 판정에서
되돌려졌다; 실험 부록, B).

**ZCode.** 중국어에는 GLM(Z.ai, 대화형 ZCode 도구 사용)이 참고용 세 번째 의견을 낸다.

**v1.0 검증셋 결과**(무작위 행; 시범의 라운드별 결과는 실험 부록, B):

| 표본 | 두 검수자가 모두 바꾼 행 | 그중 관문이 이미 보류한 행 | 학습에 들어가는 행의 오류율 |
|---|---|---|---|
| 300행 (Haiku 90% / Sonnet 10%) | 10 (3.3%) | 2 | 8 / 298 (2.7%; 95% 구간 ≈ 1.4–5.2%) |
| Sonnet 100행 | 5 (5%) | 3 (놓친 이름 셋 모두) | 2 / 97 (2.1%) |
| 중국어 100행, GLM 대 생성기 | 경계 100%, 레이블과 수준 98.9%, 하위 유형 95.7% | | 생성기의 명백한 오류 1건 |

「이미 보류」 행은 자동 관문의 검토 표시(필수 하위 유형이나 PII 개수 누락, 형식에 안 맞는 값)가 붙어 학습에 들어가지 않는다. 두
검수자는 둘 다 찾은 모든 스팬의 레이블, 수준, 하위 유형에서 서로 일치한다. 300행 중 8행에서는 둘이 달라, 그 행은 생성기
레이블을 유지하거나 보류되었다. 테스트셋은 표본 대신 전수 이중 검수를 받는다(보고서 4.2절). 공개 테스트 17,058행 중 318행(1.9%),
비공개 테스트 17,001행 중 223행(1.3%)이 바뀌었다.

학습한 교사 모델이 레이블 오류를 자동으로 찾을 수 있는지는 이전 모델로 시험했다(실험 부록, I.4). 교사 모델은 실제 오류를
5–10배 농축하지만 표시의 3분의 2가 틀리므로, 자동으로 레이블을 다시 붙이지 않는다.

## M11. 중복 제거와 누출

템플릿 재사용은 세 단계로 검사한다.

1. **완전 중복.** NFKC 정규화와 공백 축약 후의 완전 중복은 각 분할 안에서, 그리고 우선순위가 더 높은 분할에 대해(학습, 다음
   검증, 비공개 테스트, 공개 테스트 순) 제거한다.
2. **근사 중복.** 모든 텍스트를 마스킹하고(PII 값을 레이블로 대체), 소문자로 바꾸고, 문장부호를 없앤 뒤, 단어 5-그램으로
   싱글링(shingling)한다(중국어, 일본어, 태국어, 크메르어와 공백이 적은 텍스트는 문자 5-그램). 순열 128개의 MinHash와 4행씩
   32밴드의 LSH가 후보를 내고, 싱글 집합의 정확한 Jaccard(≥ 0.7)로 확정한다. 8단어 미만(문자 모드에서는 20자 미만)인 텍스트는
   완전 일치 검사만 받는다. `<PERSON>` 하나만 있는 셀은 모든 것과 맞아떨어지기 때문이다. 질의 하나는 버킷·밴드당 검증셋은 최대
   50개, 테스트셋은 최대 500개의 참조만 보며, 상한에 걸린 질의는 따로 센다. 행은 항상 우선순위가 낮은 분할에서만 제거하며,
   학습에서는 절대 제거하지 않는다.
3. **재현율 점검.** 무작위 학습 행을 변형하고(값 교체, 단어 10% 뒤섞기, 문장부호 변경) 테스트 분할처럼 검색한다.

**누출.** v1.0 검증셋과 학습 첫 샤드 사이에는 근사 중복 템플릿이 없지만(완전 중복 35건은 검증셋에서 제거), **값**은 다시
나온다. 전체 학습 데이터와 대조하면 검증셋 PERSON 값의 44%, DATE_OF_BIRTH 값의 61%, 전체 스팬의 23%(정규화 후 29%)가 학습
데이터에도 나온다. 공개 테스트에서는 36%, 46%, 20%(25%), 비공개 테스트에서는 36%, 50%, 20%(26%)다. (첫 학습 샤드만 대조했을
때 검증셋의 비율은 26%, 35%, 12%(16%)였다.) 그래서 PII 값이 모두 학습 데이터에 없는 공개 테스트 행도 따로 채점한다. PII가 있는
10,196행 중 7,442행(73%; 정규화 기준 6,681행)이다. 여기서 네 학생 모델은 PII 문자의 1.5 / 2.0 / 2.6 / 3.2%를 놓친다(large부터
nano 순; 정규화 기준 부분집합에서는 1.5 / 2.0 / 2.5 / 3.1%). 전체 행에서는 1.6 / 2.1 / 2.7 / 3.3%, 학습 데이터에 나온 값이 하나
이상 있는 행에서는 1.7 / 2.3 / 3.1 / 3.7%다(배포 파일, 보고서 6절과 같은 예측과 채점기).

## M12. 다양성

v1.0 검증셋: 다른 호출에 다시 나오는 전체 이름은 언어별 전체 이름 스팬의 중앙값 1.4%다(M5). 값 바꾸기 뒤, 바꾼 유형에서 가장
흔한 값은 그 유형 스팬의 3.3% 이하다(M8). PII 없는 항목의 52.7%가 변형 요소를 갖는다(M3). 고유 단어 3-그램 비율은 PII 없는
항목과 PII 항목 모두 약 0.95다(0.955와 0.953; 그룹당 무작위 3,000개 항목, 중국어·일본어·태국어·크메르어 제외). 학습 샤드마다
같은 결과다. PII 없는 항목 0.948–0.957, PII 항목 0.953–0.961(학습 전체 0.947과 0.953).

## M13. 데이터셋 버전과 레이블 대응

**버전 1.0**(태그 `data-v1.0`): 검증셋과 학습 데이터의 첫 8분의 1은 이전 프롬프트 버전에서 나왔고 v1.0 값 바꾸기로 후처리했다.
최종 프롬프트 버전과의 차이는 복구 구절을 필수로 배정할 수 있는 곳(칸이나 한 줄 항목에는 배정하지 않음)과 지침 세 줄(복구 구절,
결제 전용 사용자 번호, 전체 자릿수 수신자 부담 번호)뿐이다.

**레이블 대응.** v1.0의 모델 레이블은 M1의 13개다. PERSON의 surname, alias, initials는 PERSON_L2, 공개 URL은 URL_L2가 되고(학습
스팬의 7.7%: PERSON 스팬의 23%, URL 스팬의 44%), IP 주소는 ID_NUMBER가 되며, SECRET을 학습한다(이전 10개 레이블 모델에서는
뺐다; 실험 부록, H).

## M14. 관련 연구 상세

보고서 2절은 이 글을 줄인 것이다. 참고문헌 번호는 보고서의 번호다.

### M14.1 PII 탐지 시스템

**규칙 및 NER 파이프라인.** Microsoft Presidio는 개체명 인식(named entity recognition), 정규식, 규칙 기반 로직, 체크섬에 기반한 기본 제공 또는 사용자 정의 인식기를 결합한다 [1]. 기본 설정에는 영어용 인식기와 모델만 들어 있다. 다른 언어에는 spaCy, Stanza 또는 transformers 모델과 언어별 문맥 단어가 필요한데, "각 인식기는 한 언어만 지원할 수 있기" 때문이다 [2].

**GLiNER와 PII 변형.** GLiNER는 레이블로 주어진 임의의 개체 유형을 추출하는 작은 양방향 인코더 모델이다 [3]. PII용 미세조정 모델로는 합성 PII 데이터셋으로 학습한 `gliner_multi_pii-v1` [4]과 GLiNER2 [5] 파생 모델이 있다. 그중 하나인 GLiNER2-PII(205M 파라미터)는 7개 유럽 언어에서 42개 유형을 다루며, 비유럽 문자에서의 성능은 측정하지 않았다고 밝힌다 [6]. 또 다른 `gliner-pii-edge-v1.0`은 60개 이상의 범주를 내세운다 [7].

**OpenAI Privacy Filter.** 이 모델은 전체 1.5B, 활성 50M 파라미터에 스팬 유형 8개를 가진 양방향 토큰 분류기다. 모델 카드는 이를 "주로 영어"라고 설명하고 비라틴 문자에서 성능이 떨어진다고 경고한다 [8]. 32개 벤치마크에 걸친 독립 평가는 MultiCoNER v2 일반 NER 세트에서 페르시아어(아랍 문자) F1 약 0.038, 우크라이나어(키릴 문자) F1 0.027을 보고한다. 같은 연구에서 영어 합성 예시 약 500개로 미세조정한 XLM-RoBERTa가 이 필터의 제로샷 점수를 넘어선다 [9].

**브라우저용 및 소형 모델.** Mozilla의 smart-pii-redactor는 어휘 20k의 mMiniLMv2-L6-H384를 미세조정한다. 4비트 ONNX 변형은 14.8 MB이고 채팅 메시지를 대상으로 하며, 테스트셋은 8개 언어를 다루지만 모델 카드에 어떤 언어인지 나와 있지 않다 [10]. Rampart는 브라우저 내 사용을 위해 MiniLM-L6-H384 인코더(Q4에서 14.7 MB)를 OpenPII 1.5M으로 미세조정한다. 라틴 문자 7개 언어를 지원하며 비라틴 문자는 범위 밖이라고 밝힌다 [11]. Rampart Edge는 축소한 onnxruntime-web 빌드에서 도는 1.45 MB 4비트 모델로, 영어와 스페인어에 맞춰져 있다 [12]. Horizon의 `pii-redactor-small`(mmBERT-small, 141M)은 openpii-1.5m, Nemotron-PII, Gretel 데이터로 학습했다. OpenPII 검증셋에서 개체 F1 0.971을 자체 보고하지만, 외부 RedactionBench에서는 가림(redaction) F1이 0.351이다 [13].

**상용 API.** Google Sensitive Data Protection은 내장 infoType 목록을 문서화하며, 그중 다수가 국가별이다(예: `BRAZIL_CPF_NUMBER`, `JAPAN_INDIVIDUAL_NUMBER`) [14]. Amazon Comprehend는 영어나 스페인어 텍스트에서 PII를 탐지하며, 공통 유형에 더해 캐나다, 인도, 영국, 미국의 국가별 식별번호를 다룬다 [15].

**최근 벤치마크.** 최근 벤치마크들은 집계 점수가 실패를 가린다는 것을 보여 준다.
- REDACT(25개 언어, 9개 문자 체계)는 고민감 범주에서 Presidio의 재현율이 0.07이라고 보고한다 [16].
- RedactionBench는 문맥에 따른 가림에서 사람 간 일치도가 47.7%임을 발견한다 [17].
- PII-TRACE는 단일 패스 탐지기가 긴 대화에서 정답 문자의 약 3분의 1을 놓친다고 보고한다 [18].

우리가 찾은 공개 모델 가운데 20 MB 미만인 것은 라틴 문자 전용이거나 지원 언어를 밝히지 않았고, 더 넓은 다국어 모델은 파라미터가 100M 이상이다. *우리 연구*는 비라틴 문자를 포함한 54개 언어를 위한 2–20 MB 브라우저 모델을 목표로 하며, 이를 외부 데이터셋에서 평가한다.

### M14.2 PII 데이터셋

**ai4privacy.** ai4privacy 시리즈는 합성 데이터다.
- `pii-masking-400k`: 6개 유럽 언어로 406,896건, 공개 클래스 17개. 학술 사용을 권장하며, 상업 사용에는 라이선스가 필요하다 [19].
- `open-pii-masking-500k`: 8개 언어로 580,227건. Llama 3.1/3.3으로 생성했으며 Llama Community License를 따른다 [20].
- `pii-masking-openpii-1.5m`: 예시 1,636,375개, 레이블 19개, 언어 30개(아시아·태평양 로케일 7개 포함), CC-BY-4.0 [21].

**기타 합성 데이터셋.** NVIDIA의 Nemotron-PII는 NeMo Data Designer로 생성한 페르소나 기반 데이터셋으로 CC BY 4.0이다. 데이터셋 카드는 50개 이상 산업에 걸쳐 55개 이상의 PII/PHI 범주를 담은 영어 레코드 100,000건을 설명한다 [22]. Gretel의 `synthetic_pii_finance_multilingual`은 7개 유럽 언어의 금융 문서 55,940건에 PII 유형 29개를 담았고 Apache 2.0이다. 카드는 NER 기반 레이블링이 "거짓 음성 … 또는 거짓 양성을 만들 수 있다"고 적는다 [23]. DialogPII는 LLM이 생성하고 사람이 손본 11개 언어의 대화를 더한다 [24].

**한국어.** KDPII는 한국어 대화형 비식별화 데이터셋이다 [25]. 저자들은 모델이 한국 특유의 PII보다 보편적인 PII를 더 잘 인식한다는 것을 발견했다. 개정판(CC BY 4.0)에는 고정된 분할이 없다 [26].

**오래된 자료.** WikiANN(282개 언어) [27]과 WikiNEuRal [28] 같은 오래된 다국어 NER 코퍼스는 PII가 아니라 일반 개체 유형에 대한 위키백과 기반 준정답(silver-standard) 주석을 제공한다. 비식별화 코퍼스는 영어이고 특정 영역에 한정된다. 2014 i2b2/UTHealth 코퍼스는 임상 기록 1,304건을 [29], TAB는 유럽인권재판소(ECHR) 판례 1,268건을 담고 있다 [30].

*우리 데이터*는 언어 수(54), 국가별 식별번호 형식과 이름 풀, 그리고 직접 식별자와 간접 식별자를 나누는 PII 수준에서 다르다.

### M14.3 NER·정보 추출을 위한 LLM 생성 학습 데이터

**생성과 증류.** LLM을 주석자나 생성기로 쓰면 레이블링 비용이 준다는 것이 밝혀졌다. GPT-3 레이블은 50–96% 낮은 비용으로 사람 레이블과 맞먹었다 [31]. ZeroGen은 완전히 합성된 데이터로 작은 과제 모델을 학습한다 [32]. UniversalNER는 목표 지향 지시 튜닝(targeted instruction tuning)으로 ChatGPT의 NER 능력을 더 작은 모델로 증류한다 [33]. NuNER는 LLM이 주석한 데이터로 작은 인코더를 사전학습한 다음, 적은 예시로 개체 인식에 맞게 미세조정한다 [56].

**알려진 한계.** 알려진 한계는 다양성과 충실도에 관한 것이다. 단순한 클래스 조건 프롬프트는 편향되고 다양성이 낮은 데이터를 만들며(지역 편향 포함), 길이와 문체 같은 속성을 바꾸는 속성 지정 프롬프트(attributed prompts)는 하위 모델을 개선한다 [34]. 레이블이 주관적인 과제에서는 합성 데이터의 도움이 적다 [35]. 한 서베이는 주석 품질 평가와 잡음 섞인 LLM 레이블로부터의 학습을 다룬다 [36].

*우리 생성기*는 명시적인 설계 축을 두어 속성 지정 프롬프트 방향을 따른다. 차이는 생성기 레이블이 옳다고 가정하는 대신 블라인드 이중 검수로 레이블 오류율을 측정한다는 점이다.

### M14.4 작은 다국어 인코더와 압축

**인코더.** XLM-R은 100개 언어의 CommonCrawl 텍스트 2 TB 이상으로 사전학습되었다 [37]. mDeBERTa-v3-base는 제로샷 XNLI에서 XLM-R Base보다 약 3.6점 높다 [38]. MiniLMv2는 셀프 어텐션 관계를 증류하며, XLM-R에서 증류한 다국어 학생 모델을 포함한다 [39]. L6×H384 mMiniLMv2는 파라미터가 107M이고 XLM-R 토크나이저를 쓰므로 [40], 크기 대부분이 임베딩 행렬에 있다. mmBERT는 1,800개 이상 언어의 약 3T 토큰으로 사전학습한 최근 인코더다 [41].

**시퀀스 레이블링을 위한 증류.** 지식 증류(knowledge distillation) [42]는 다국어 NER에 적용되어 왔다. XtremeDistil은 41개 언어에서 F1의 약 95%를 유지하면서 mBERT를 파라미터 기준 최대 35배 압축한다 [43]. 구조 수준 증류는 여러 단일 언어 교사 모델의 지식을 하나의 다국어 학생 모델로 옮긴다 [44].

**어휘 축소.** 다국어 모델은 파라미터 대부분을 임베딩 계층에 두기 때문에, 필요한 언어의 토큰만 남기면 비슷한 정확도로 mBERT 파라미터를 최대 약 45% 줄일 수 있었다 [45]. 단일 언어에는 보통 어휘의 약 50%면 충분하다 [46].

**양자화와 브라우저 런타임.** GPTQ는 정확도 손실이 거의 없이 가중치를 3–4비트로 양자화한다 [47]. ONNX Runtime은 블록 단위 4비트 가중치 전용 양자화를 지원한다. MatMul은 `MatMulNBits`(RTN, GPTQ 또는 HQQ)가 되고 Gather는 `GatherBlockQuantized`가 된다 [48]. ONNX Runtime Web은 이런 모델을 WebAssembly, WebGPU 또는 WebNN으로 브라우저에서 실행한다 [49].

*우리*는 새 기법을 제안하기보다 기존 기법을 결합한다. 어휘를 가지치기한 mMiniLMv2 학생 모델로의 증류와 4비트 가중치다. 이 조합의 언어별 동작을 54개 언어에 걸쳐 보고한다.

### M14.5 평가 관행

**누출과 오염.** 학습–테스트 중복은 점수를 부풀린다. 오픈 도메인 QA에서는 테스트 질문의 약 30%가 학습 데이터에 거의 같은 바꿔 쓰기(paraphrase)를 갖고 있으며, 모델은 중복되지 않은 질문에서 훨씬 못한다 [50]. 중복 제거는 학습–검증 중복도 줄이는데, 이 중복은 표준 검증셋의 4% 이상에 영향을 준다 [51]. NER에서는 처음 보는 개체가 일반화 격차의 상당 부분을 만든다 [52]. LLM 학습 데이터에 의한 벤치마크 오염도 추가 우려 사항이다 [53].

**익명화 품질.** 스팬 지표는 마스킹된 텍스트가 여전히 사람을 식별하는지 보여 주지 않는다. Textwash는 익명화 도구를 정확도, 잃은 정보, 그리고 익명화된 묘사에서 사람들이 여전히 그 인물을 알아볼 수 있는지로 평가한다 [57]. 우리는 스팬 수준 지표만 보고한다.

**실행 간 편차.** 랜덤 시드만으로도 NER F1이 약 1점 움직이며 유의한 차이를 낼 수 있다 [54]. 가중치 초기화와 데이터 순서도 미세조정 편차에 비슷하게 기여한다 [55].

*LLM 생성기는* 독립적으로 시드를 준 분할 사이에서도 이름과 값을 재사용하므로, 우리는 본 값과 처음 보는 값의 부분집합을 따로 보고한다. 부트스트랩 구간은 테스트셋 표본 추출만 반영한다. 학습 편차는 반복 실행이 있는 경우에 그것으로 따로 보고한다.

## M15. 외부 평가셋

**표본.** `training/scripts/ext_data.py eval`은 `training/eval_sets/manifest.json`의 ID(데이터셋 버전, 행 순서대로의 ID, 출력의
SHA-256)로 각 표본을 다시 만들고, 파일이 하나라도 다르면 실패한다. 표본은 v1.0 모델이 생기기 전인 2026-10-28에 뽑았다:

- **openpii-1.5m** (`ai4privacy/pii-masking-openpii-1.5m`, revision `a785eb5`): test split이 없어 validation split을 쓴다. 시드
  20261028의 저장소 표집(reservoir sampling)으로 언어당 200행을 뽑았다. 같은 난수 흐름으로 training split을 먼저 한 번 훑었으므로,
  결과 uid를 manifest에 적어 둔다.
- **KDPII** (Zenodo 16759166, v2): 공식 split이 없다. 문서 4,981개를 시드 20261028로 섞어 앞 85%(4,233개)를 학습 쪽, 나머지(문서
  748개, 문장 8,129개)를 테스트 쪽으로 둔다. 문서 단위로 나누므로 한 대화의 문장이 양쪽에 걸치지 않는다. manifest에 두 문서 목록이
  모두 있다.
- **Nemotron-PII** (`nvidia/Nemotron-PII`, revision `b70ffaf`): test split에서 로케일(`us`, `intl`)당 1,000행,
  `pandas.sample(random_state=20261028)`. 같은 uid가 두 로케일에 반복되므로 ID는 `<locale>:<uid>`다.
- **Gretel finance** (`gretelai/synthetic_pii_finance_multilingual`, revision `7b844d1`): test split에서 같은 방법으로 언어당
  최대 400행. ID는 test 파일의 행 위치다.

**평가용 대응** (`external_sets.py`).
- **이름과 주소.** 이름과 성은 PERSON이 되고 붙어 있으면 합친다. 도로명, 건물 번호, 우편번호, 좌표는 ADDRESS가 된다. 도시·군·주·국가는
  닿아 있는(4자 이내) ADDRESS에 붙고, 아니면 무시한다.
- **식별번호와 계좌.** 계좌, 카드, 라우팅, SWIFT 번호는 FINANCIAL이 된다. 개인 식별번호(SSN, 여권, 면허, 번호판, 기기, IP)는
  ID_NUMBER가 된다.
- **사용자명, 생년월일, 비밀값.** 사용자명은 USERNAME, 생년월일은 DATE_OF_BIRTH가 된다. 비밀번호, PIN, API 키, 쿠키는 SECRET이 된다.
- **무시.** `[Guest Name]` 같은 자리표시자는 값이 아니다. Nemotron과 Gretel에서는 나머지 유형이 모두 `ignore` 스팬이다(PII로도
  과잉 마스킹으로도 세지 않음).
- **openpii.** DATE는 앞 40자 안에 출생 단서가 있을 때만 DATE_OF_BIRTH가 된다. CITY는 다른 주소 조각과 3자 이내일 때만 ADDRESS가
  된다.
- **KDPII.** 이름과 별명은 PERSON, 직장·학교·부서는 ORG가 된다. 주소는 숫자가 있을 때만 ADDRESS다(서울시 같은 지역명만 있으면
  마스킹하지 않음).
- **대응되지 않는 유형.** openpii와 KDPII에서는 처음 만들 때처럼 스팬으로 만들지 않는다.

**학습용 대응** (`ext_data.py train`, 우리 데이터와 외부 학습 쪽을 함께 학습하는 모델용. 검토 후 기각했다 — 실험 부록 N).
평가 표본이 나온 쪽은 읽지 않는다. 읽는 것은 openpii training split, KDPII 학습 쪽 문서, Nemotron과 Gretel의 training split이다.
그다음 평가 표본과 완전히 같거나 템플릿이 같은 행을 `dedupe_splits.py`로 지운다(평가 표본을 우선순위 1로 둠). v1.0 체계가 더
세밀한 곳에서는 평가용 대응과 다르다:
- **수준 2.** 이름과 합쳐지지 않은 성은 PERSON_L2다. KDPII 별명도 PERSON_L2다.
- **URL.** 공개 URL과 개인 URL을 구분하지 않으므로 `ignore`다.
- **날짜.** 출생 단서가 없는 날짜는 "PII 아님" 대신 `ignore`다.
- **대응되지 않는 유형.** 모두 `ignore`다.
- **`known` 레이블.** 각 행에는 그 출처가 라벨을 다는 v1 레이블 목록이 있다. 예를 들어 openpii는 ORG, URL, SECRET에 라벨을 달지
  않는다. 그래서 학습 코드가 출처가 아예 표시하지 않는 유형을 "PII 아님"으로 배우지 않게 할 수 있다.
